Growth from trained weights · interactive comparison

Depth and width from existing weights

Three ways to build a bigger network out of one you already trained. One guarantees the function survives the operation, one deliberately does not, and one never touches the old network at all. The difference is not size — it is what the old weights are allowed to become.

Not human-reviewed Automated readings of the public arXiv and ar5iv sources; check the linked review drafts before reusing details.

Net2Net · Chen, Goodfellow & Shlens 2016 · function-preserving expansion

Widen a layer without changing what it computes

The two-unit hidden layer below is widened to three by copying unit 1 under the mapping g = [0, 1, 0]. Net2WiderNet then divides each copied unit's outgoing weight by its replication count, "so all the units have the exactly the same value as the unit in the original net". Turn that division off and watch the guarantee go.

And depth?

Net2DeeperNet inserts a layer initialized to the identity, "but remains free to learn to take on any value later". It works only where the activation satisfies φ(Iφ(v)) = φ(v) — true for the rectified linear activation used here, and, the paper states, not possible for the logistic sigmoid. The exported net2Deeper in this module's demo.js does exactly that, and the test suite checks the deepened network's output is unchanged.

The paper adds noise to every copy but the first on purpose: identical copies would move together forever, so the student is made "only approximately the same function as the teacher" in exchange for being able to use its new capacity.

G_stack · Du et al. 2024 · re-trained expansion

Stack a trained model on itself, then keep training

The same paper's taxonomy has four atomic operators — duplicate (G_direct), learn a mapping (G_learn), zero (G_zero), random (G_random) — each depthwise or widthwise. G_stack is depthwise duplication: the target is M∘M∘⋯∘M, g times, where M is a small base model trained on d tokens.

Function preserved?No — and it is not meant to be

Nothing is frozen after growth: the grown model is pre-trained further, and the paper's claim is a cheaper path to a given loss, not an unchanged function. The paper's fitted equation for when to grow rendered ambiguously in the source read here, so this module asserts no growth-timing formula.

Progressive networks · Rusu et al. 2016 · frozen columns with lateral reuse

Never expand the old network — read it

A new task gets a new randomly initialized column. Every earlier column is frozen, and each layer of the new column reads the corresponding layer of every earlier column through lateral connections: hi(k) = f(Wi(k) hi-1(k) + Σj<k Ui(k:j) hi-1(j)).

Earlier tasks disturbedNone, by construction

The paper's own reason: "because also the parameters {Θ(j); j<k} are kept frozen … there is no interference between tasks and hence no catastrophic forgetting". Its own stated downside: the parameter count grows with the number of tasks. Both belong in the same sentence.

Three different promises

Net2Net — preserved at the instantThe bigger network computes exactly the old function the moment it is built; afterwards everything trains, and noise on the copies is added so the new capacity can diverge.
G_stack — re-trainedThe trained weights are carried forward as an initialization, not as a function. Duplication preserves nothing; the payoff is measured in pre-training compute.
Progressive — preserved permanentlyOld columns are constants for the optimizer, so every earlier task keeps its exact function forever. Reuse is one-directional and paid for in parameters.

Function preservation is not one property. Net2Net preserves the current function for an instant; progressive networks preserve every old task's function permanently and refuse to grow the old network at all; G_stack preserves nothing and says so.

The pre-transformer lineage

These three did not invent the questions. Two existing modules in this book hold the earlier form of each:

  • Topology growth comparison — Growing Neural Gas and Grow When Required insert units into a structure that keeps adapting, which is expansion without any preservation guarantee: the ancestor of the G_stack position.
  • What counts as evidence for more capacity? — Dynamic Node Creation, Cascade-Correlation and the Resource-Allocating Network answer when to grow. Cascade-Correlation's frozen installed inputs are the ancestor of the progressive-network column, at the scale of one unit rather than one network.
  • Where do the new parameters live? — adapters, LoRA and MoLE take the freezing idea to its modern conclusion: freeze everything trained and add beside it.

The through-line is narrow and worth stating precisely: the old work asked when to add capacity and mostly kept training everything; the modern work asks what the addition is initialized from and what it is forbidden to disturb.
